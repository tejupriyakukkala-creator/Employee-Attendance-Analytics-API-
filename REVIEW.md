# REVIEW.md

## Starter Code Review (`app/main.py`)

List of defects identified in the starter application, their impact, how they were reproduced, and how they were resolved:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33-37) | Grace period logic used `minutes > 10` after integer floor. For 09:40:01 (601 seconds), `int(601/60) = 10`, and `10 > 10` evaluates to False, returning 0 instead of 10. Also lacked IST timezone conversion and overnight shift awareness. | Punch in at 09:40:01 for a 09:30 shift returned 0 instead of 10 late minutes. | Checked `diff_sec > 600` strictly after `shift_start` in IST, then calculated floor minutes `int(diff_sec // 60)` since shift start per R2. |
| 2 | `compute_work_hours` (lines 40-42) | Used Python's built-in `round()`, which applies banker's rounding (round half to even, e.g. 2.505 -> 2.50) instead of half-up rounding (R4). | Duration of 2.505 hours rounded to 2.50 instead of 2.51. | Replaced with `Decimal(str(diff_sec / 3600)).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)`. |
| 3 | `compute_overtime` (lines 44-48) | Missing 30-minute threshold: returned overtime even when under 30 minutes. Also placed overnight shift end on the same calendar day instead of the next day. | Punch-out 5 minutes after shift end returned 5 instead of 0. Overnight shifts produced negative or erroneous durations. | Added `diff_sec >= 1800` check (returning 0 otherwise), and added +1 calendar day in IST when `shift_end <= shift_start` (overnight). |
| 4 | `health` (lines 72-74) | Did not ping MongoDB; always returned 200 even when database was down. Contract requires 503 when MongoDB is unreachable. | Simulated database downtime and endpoint still returned 200 OK. | Executed `database.client.admin.command("ping")` inside a try/except block; raises HTTPException 503 on failure. |
| 5 | `create_employee` (lines 77-85) | Check-then-insert race condition (`find_one` then `insert_one`). Lacked Pydantic schema validation (regex patterns, shift difference). `created_at` was local naive datetime and serialized incorrectly. | Concurrent creation of identical `emp_code` created duplicate records or unhandled crashes; accepted `shift_start == shift_end`. | Enforced unique index on `emp_code` and caught `DuplicateKeyError` to return 409; added validation rules to Pydantic model; serialized `created_at` as epoch ms. |
| 6 | `list_employees` (lines 88-96) | Off-by-one pagination bug (`skip = page * page_size` skips first 20 records for `page=1`). `total` counted the whole collection instead of matching the filter. Missing sort and epoch ms serialization. | Calling `/employees?page=1` skipped the first 20 employees. `/employees?department=X` reported total of all employees. | Changed skip to `(page - 1) * page_size`, counted filtered documents `count_documents(q)`, added `.sort("emp_code", 1)`, and serialized dates to epoch ms. |
| 7 | `punch_in` (lines 99-122) | Crashed with 500 `TypeError` on missing employee. Date calculated with server local timezone instead of IST; overnight shift previous-day rule ignored. Instants not truncated to whole seconds. Injected non-contract `id` field. Status unvalidated. | Nonexistent employee returned 500; overnight punch-ins were assigned to the wrong date; response included `id` field forbidden by contract. | Checked employee existence (404); truncated instants to whole seconds; calculated IST attendance date per R1; enforced unique compound index `(emp_code, date)` with 409 on race; formatted response without `id`. |
| 8 | `list_attendance` (lines 124-151) | Loaded entire collection into Python memory with `list(db.attendance_logs.find(q))` before sorting. Failed on 100k scale. Missing date range validation (`date_from > date_to`). Returned `id` and raw datetime objects. | Memory exhaustion on large datasets; `/attendance?date_from=2026-07-10&date_to=2026-07-01` returned 200 instead of 422. | Performed sorting and pagination inside MongoDB using `.sort([("date", -1), ("emp_code", 1)]).skip(skip).limit(page_size)`; added 422 validation for date range; formatted epoch ms. |
| 9 | Missing endpoints (lines 154-162) | 7 endpoints were completely missing: punch-out, regularization PATCH, employee monthly analytics, department summary, late leaderboard, department trend, and admin explain. | Calling any of these endpoints returned 404 Not Found. | Implemented all 7 endpoints strictly matching `openapi.yaml` contract, business rules R1-R10, and MongoDB aggregation pipelines. |
| 10 | Startup initialization | No database indexes created at startup. Queries would perform full collection scans (COLLSCAN) on large datasets. | `/admin/explain` failed index checks. | Implemented FastAPI `lifespan` handler that creates all required unique and compound indexes idempotently on startup. |

## Items Examined and Decided Were NOT Defects

1. **PyMongo synchronous driver with FastAPI threadpool:** FastAPI runs standard synchronous `def` endpoints in an AnyIO worker threadpool (`run_in_threadpool`), allowing blocking PyMongo calls to execute concurrently without starving the main async event loop. This is efficient, battle-tested, and avoids async driver complexities.
2. **Reading `MONGO_URI` and `MONGO_DB` via `dotenv` with system env precedence:** `load_dotenv()` loads local `.env` as default fallback without overriding real environment variables already set in the operating system or grading runner.
3. **Pydantic V2 model structure:** Standard Pydantic V2 models provide high-performance request and response serialization and automated OpenAPI schema generation.
